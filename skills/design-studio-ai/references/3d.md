# 3D scenes

Read [shared layout and quality](layout-and-quality.md) first. Use this for `kind: "3d"`; inspect the `object-study` template and the live schema.

## Composition and supported scene data

Establish the subject, intended viewpoint, material story, and destination format. Stage actual `model3d` nodes and `group` parents in scene space. Use `scene.position`, `scene.rotation`, and `scene.scale` for object transforms; rotations are in degrees. Set page `scene.camera` (`position`, `target`, `fov`), `ambient`, and `light` (`position`, `intensity`, `color`) for a deliberate view. Orbiting a preview is not proof that the stored camera changed.

Supported primitives are selected with `data.geometry` (box, sphere, torus, torusKnot, cone, cylinder). A `scene.mesh` uses vertex `positions`, triangle `indices`, and optional UVs, normals, tangents, colors, morphs and weights; imported GLB uses an owned asset `src`. Use `scene.material` for supported PBR properties and map references. Page `scene.lights` adds point/spot/directional lights; `atmosphere`, `rendering` and seeded `emitters` control fog, exposure/environment, shadows, bloom and timed particles. Discover limits through `/api/schema`; do not invent shader code, physics or arbitrary asset loaders. Editor/viewer and raster/video share these effects; GLB/glTF does not carry the Studio fog/bloom/environment or timed-particle effect stack.

Upload is library-only; insert the asset explicitly. Inspect an imported model with WebMCP `studio_imported_model({pageId,nodeId})` before selecting named clips. Place exact inventory names in `scene.importedClips` with `start`, `end`, optional `speed`, `weight`, `loop`. Use the inspector to review actual playback. Set `convert:true` to preview editable conversion, then `preview:false` to apply after checking the report. Supported PBR maps, meshes, skins, position morphs and placed animation become native editable data; a hidden source checkpoint retains the original GLB asset. Nonunit rest/animated bone scale, unsupported physical materials, authored morph normals/tangents, instancing and unsupported UV channels are rejected rather than dropped.

Network conversion uses export `format:"editable-scene"` with `pageIndex` and `nodeId`: REST `/api/projects/{id}/export`, MCP `export_project`, CLI `projects export PROJECT --format editable-scene --node NODE --output editable.json`. It returns canonical JSON without saving, retaining project asset references rather than bundling portable files. Review it and use an ordinary observed-revision document write. No network equivalent of the local import/framing tool should be guessed. Preserve the source asset and use external authoring when conversion rejects the model.

For rigging, parent bones precede children; valid meshes need matching UV and skinning arrays, existing bone indices, and four skin indices/weights per vertex. Preserve the bind pose when inspecting animation. Use the existing mesh/UV/rig tools instead of replacing validated scene data with executable code.

## Design choices

- Prefer a clear silhouette, readable scale relationships, and intentional negative space. Check camera perspective before adding geometry.
- Light the important form; avoid blown highlights, muddy material contrast, or unnecessary high metalness. Inspect textures for seams, stretching, and resolution at the intended view.
- Keep objects and rigs only as complex as the requested effect needs. Repeated detail should add meaning rather than slow interaction.
- Flex is useful for accompanying labels, legends, or a surrounding 2D explanation. It is not a substitute for 3D transforms and camera framing.

## Review and delivery

Inspect the real WebGL scene from the delivery camera and several orbit angles. Check clipping, intersections, visibility, material appearance, texture mapping, transparent surfaces, and parent transforms. For animated rigs, inspect start/end poses and intermediate extremes; check deformations and maintain the stored bind pose. Review accompanying text for ordinary canvas overflow too. Geometry preflight alone cannot establish scene quality.

GLB/glTF carries supported scene geometry/materials and sampled animations, not the whole 2D web page or arbitrary runtime behavior. Animation export has a sampled-value budget; reduce duration, frame rate, or animated joints when the exporter reports its limit. Reopen the actual file and inspect textures, transforms, and animation.

For automatic framing, set `page.scene.camera.safeFrame` (0–0.3) and use WebMCP `studio_frame_scene_shot` with `pageId`, observed `nodeIds`, `samples` (2–61, default 17), optional `aspect:"portrait"|"square"`, and `preview` (default true). Apply with `preview:false` after reviewing. It fits sampled posed bounds, optionally on a duplicated page sharing assets. Inspect intermediate wing/tail extremes and overlays; a sampled fit is not a continuous clipping guarantee. Network clients edit the same camera/page fields through existing document operations.

Audio/video node `data` stores `audioStart`, `audioEnd`, `audioOffset`, `audioGain`, `audioMuted`, `audioLoop`, `audioEvent`. Times are seconds, gain is 0–4, and the event is a label rather than generated sound. Timeline waveform/trim controls and browser/cloud video exports share cue timing and mixing. Import sources first and listen to an actual export; still images and GLB have no soundtrack. Shared `replace-asset` updates existing asset references while retaining placements/timing; verify the replacement's clip inventory and duration.

Raster/PDF/video rendering can capture real WebGL. Keep 3D objects that need mutual depth testing together in layer order: a 2D caption separates 3D segments. Reparent/reorder through the existing operations; avoid an opaque full-page shape above a scene that should remain visible.

Material finishes are starting points; inspect the result under the delivery lighting. Texture import uses an owned asset referenced by `scene.material.textureAssetId`. When changing a material through `update-node`, preserve the rest of the `scene` object you read so transforms, meshes, or rigs are not discarded. Apply the same rule to page `scene` changes for camera and lighting.

Static SVG uses a symbolic representation rather than an actual scene screenshot. HTML can include the trusted scene viewer. Import external media before cloud export, check renderer availability, and never deliver the SVG symbol as proof of the finished 3D scene.

## Character authoring commands

Discover `sceneCommands` from the live schema. Prefer WebMCP `studio_scene_command` (preview defaults true) and `studio_inspect_scene` to constructing large vertex buffers. The saved-state equivalents are MCP `author_scene` / `inspect_scene` and CLI `scene command` / `scene inspect`. Remesh supports unparented primitives and bounded document meshes; loft gives explicit joint rings. Create landmark-based quadruped rigs, bind and inspect weights, attach accessories before adding preset clips, and inspect sampled deformation. Morph targets, UV islands and texture strokes persist and export. Read the product 3D character guide for limits; automatic rigging is a starting point, not proof of animation quality.

Use `share-rig` only after inspecting compatible legacy attachments; it deduplicates shared skeleton/clip data without forcing incompatible bind spaces. Prefer `edit-clip` for focused amplitude/speed/loops/blend edits. Use `contact` for persistent world-space stance intervals and inspect full-animation contact errors. Brush locks, mesh checkpoints, plane-cut loops and material layers share the scene command schema. Automatic anatomical quad retopology is not provided.

`rig-winged-quadruped` requires explicit hips/chest/head/feet/tail landmarks, jaw/jawTip, and each wing's shoulder/elbow/wrist plus 3–5 finger base/tip pairs. It does not infer anatomy. Use named `joint-limits` and `mirror-pose` for constrained FK. `clip` presets `wing-flap` and `roar` add wing/jaw motion; `wristLag` controls delayed wrist motion. They reject missing native bone names and do not retarget arbitrary imported rigs. Bind and inspect continuous-surface deformation rather than accepting disconnected rigid pieces as skinning. Add a sound cue separately for an audible roar.

For long saves, use browser `studio_start_save` with a retained operation ID, poll its status, then `studio_reconcile_save`. Network MCP uses `start_operation/get_operation/get_operation_result`; CLI uses `operations start/status/result`. Retry the identical ID and payload after an uncertain response; never invent a newer revision. Export `scene-angles` at `start` for the four existing PNG names, or add `end` and `reviewSamples` (2–25, default 5) for four real views at every sampled time, a contact sheet and camera/node/time diagnostics in `views.json`. CLI maps these to `--start`, `--end`, `--review-samples`; REST and MCP `export_project` use the camelCase fields. All rendered images plus the sheet must fit 64 megapixels. This review count is separate from scan/framing `samples` and frame-archive `fps`. Open the actual images; clipping diagnostics do not prove absence of occlusion. Export GLB for interchange, then reopen bytes and verify maps, skin and clips.

Full-animation scans emit informational seam diagnostics only in the first frame; warning locations remain time-indexed.
